# DATABASE.md

Status: **schema design for M1+. No database exists yet.** This document is the
contract that migrations must implement. If a migration and this document
disagree, the migration is wrong until the document is updated deliberately.

## 1. Conventions

- PostgreSQL 18.
- Primary keys: `uuid` generated by `gen_random_uuid()` (built into PG 13+).
- Public identifiers: UUID only. Sequential integer IDs are never exposed.
- Instants: `timestamptz`, stored in UTC.
- Media positions and durations: `bigint` **microseconds**, columns suffixed
  `_us`. Millisecond rounding happens only at export.
- Frame rate and timebase: exact rational pairs `*_num` / `*_den`, never a
  rounded float.
- Enumerations: `text` + `CHECK` constraints, with matching Python enums.
  PostgreSQL native enums are avoided because adding values requires invasive
  migrations.
- Naming: plural `snake_case` tables, `snake_case` columns, constraint names
  generated by the SQLAlchemy naming convention.
- All foreign keys are explicit; `ON DELETE` behaviour is chosen per relation.
- `created_at` / `updated_at` are `timestamptz NOT NULL DEFAULT now()`;
  `updated_at` is maintained by the application (and by a trigger where
  practical).

## 2. Relationships

```text
media_assets 1 ── N processing_jobs
media_assets 1 ── N intertitles
processing_jobs 1 ── N intertitles
media_assets 1 ── N subtitle_tracks
subtitle_tracks 1 ── N subtitle_entries
subtitle_tracks 1 ── N export_artifacts
intertitles 1 ── N subtitle_entries   (optional provenance link)
```

Ownership rules:

- **`intertitles` are immutable detection evidence.** After a job completes,
  only `review_status` may change. Text and timing are never edited in place.
- **`subtitle_entries` are the single editable source of truth** for exports.
  Corrections are applied here.
- An entry may reference the intertitle it came from (`source_intertitle_id`)
  for provenance; the link is `ON DELETE SET NULL` so deleting evidence never
  destroys the deliverable.

This avoids storing the same mutable subtitle text in two places while keeping
audit evidence.

## 3. Tables

### 3.1 `media_assets`

| Column | Type | Constraints |
|---|---|---|
| `id` | uuid | PK, default `gen_random_uuid()` |
| `original_filename` | text | NOT NULL, display only |
| `storage_key` | text | NOT NULL, UNIQUE, server-generated |
| `content_type` | text | NOT NULL |
| `byte_size` | bigint | NOT NULL, `> 0` |
| `sha256` | char(64) | NOT NULL, UNIQUE |
| `duration_us` | bigint | NULL until probed, `> 0` when set |
| `width` | integer | NULL, `> 0` when set |
| `height` | integer | NULL, `> 0` when set |
| `frame_rate_num` | integer | NULL, `> 0` when set |
| `frame_rate_den` | integer | NULL, `> 0` when set |
| `time_base_num` | integer | NULL, `> 0` when set |
| `time_base_den` | integer | NULL, `> 0` when set |
| `probe_status` | text | NOT NULL, `IN ('pending','ok','failed')` |
| `probe_error_code` | text | NULL |
| `created_at` | timestamptz | NOT NULL, default `now()` |
| `updated_at` | timestamptz | NOT NULL, default `now()` |
| `deleted_at` | timestamptz | NULL (soft delete; file purge is explicit) |

Indexes: `UNIQUE (sha256)`, `UNIQUE (storage_key)`,
`INDEX (created_at DESC)`.

Notes:

- `sha256` deduplication is a product decision to be implemented in M2; the
  constraint is present from the first migration.
- `storage_key` never contains user input.

### 3.2 `processing_jobs`

| Column | Type | Constraints |
|---|---|---|
| `id` | uuid | PK |
| `media_asset_id` | uuid | NOT NULL, FK → `media_assets(id)` ON DELETE CASCADE |
| `state` | text | NOT NULL, `IN ('queued','validating','detecting','ocr_processing','review_required','completed','failed','cancelled')` |
| `stage` | text | NULL, human-readable sub-step (e.g. `frame_sampling`) |
| `progress` | smallint | NOT NULL DEFAULT 0, `BETWEEN 0 AND 100` |
| `config` | jsonb | NOT NULL DEFAULT `'{}'` |
| `attempt` | smallint | NOT NULL DEFAULT 0, `>= 0` |
| `max_attempts` | smallint | NOT NULL DEFAULT 3, `BETWEEN 1 AND 10` |
| `idempotency_key` | text | NULL |
| `error_code` | text | NULL |
| `error_message` | text | NULL, safe for user display |
| `recoverable` | boolean | NULL |
| `claimed_by` | text | NULL |
| `lease_expires_at` | timestamptz | NULL |
| `run_after` | timestamptz | NOT NULL DEFAULT `now()` |
| `created_at` | timestamptz | NOT NULL DEFAULT `now()` |
| `started_at` | timestamptz | NULL |
| `completed_at` | timestamptz | NULL |
| `updated_at` | timestamptz | NOT NULL DEFAULT `now()` |

Indexes and constraints:

- `UNIQUE (media_asset_id, idempotency_key)` where key is not null.
- Partial unique index for one active job per media:

  ```sql
  CREATE UNIQUE INDEX uq_processing_jobs_active_per_media
    ON processing_jobs (media_asset_id)
    WHERE state IN ('queued','validating','detecting','ocr_processing','review_required');
  ```

- `INDEX (state, run_after)` for claiming.
- `INDEX (media_asset_id, created_at DESC)`.
- `CHECK (recoverable IS NULL OR state IN ('failed','queued'))` is **not**
  used; recoverability is meaningful for failed attempts and is cleared on
  requeue by the service.

Job state transitions are defined in `ARCHITECTURE.md` §4 and enforced by the
service layer. The database enforces valid state values and the active-job
uniqueness, but not the full transition graph.

### 3.3 `intertitles`

| Column | Type | Constraints |
|---|---|---|
| `id` | uuid | PK |
| `media_asset_id` | uuid | NOT NULL, FK → `media_assets(id)` ON DELETE CASCADE |
| `job_id` | uuid | NOT NULL, FK → `processing_jobs(id)` ON DELETE CASCADE |
| `start_us` | bigint | NOT NULL, `>= 0` |
| `end_us` | bigint | NOT NULL, `> start_us` |
| `text` | text | NOT NULL (may be empty if OCR found nothing; see note) |
| `ocr_confidence` | numeric(5,4) | NULL, `BETWEEN 0 AND 1` |
| `detector` | text | NOT NULL (`native` or `stum`) |
| `detection_metadata` | jsonb | NOT NULL DEFAULT `'{}'` |
| `review_status` | text | NOT NULL DEFAULT `'machine'`, `IN ('machine','reviewed','rejected')` |
| `created_at` | timestamptz | NOT NULL DEFAULT `now()` |
| `updated_at` | timestamptz | NOT NULL DEFAULT `now()` |

Indexes and constraints:

- `CHECK (end_us > start_us)`.
- `UNIQUE (job_id, start_us, end_us)` prevents duplicate intervals from a
  retried stage.
- `INDEX (media_asset_id, start_us)`.
- `INDEX (job_id)`.

Note: an empty `text` is allowed only when the detector kept an interval but OCR
returned nothing; the review UI must surface it clearly. It must not silently
become an empty subtitle entry.

### 3.4 `subtitle_tracks`

| Column | Type | Constraints |
|---|---|---|
| `id` | uuid | PK |
| `media_asset_id` | uuid | NOT NULL, FK → `media_assets(id)` ON DELETE CASCADE |
| `name` | text | NOT NULL |
| `language_tag` | text | NULL, BCP-47 when known |
| `source` | text | NOT NULL, `IN ('ocr','manual')` |
| `status` | text | NOT NULL DEFAULT `'draft'`, `IN ('draft','reviewed','exported')` |
| `created_at` | timestamptz | NOT NULL DEFAULT `now()` |
| `updated_at` | timestamptz | NOT NULL DEFAULT `now()` |

Indexes: `UNIQUE (media_asset_id, name)`, `INDEX (media_asset_id)`.

### 3.5 `subtitle_entries`

| Column | Type | Constraints |
|---|---|---|
| `id` | uuid | PK |
| `track_id` | uuid | NOT NULL, FK → `subtitle_tracks(id)` ON DELETE CASCADE |
| `sequence` | integer | NOT NULL, `>= 0` |
| `start_us` | bigint | NOT NULL, `>= 0` |
| `end_us` | bigint | NOT NULL, `> start_us` |
| `text` | text | NOT NULL |
| `source` | text | NOT NULL, `IN ('ocr','manual')` |
| `source_intertitle_id` | uuid | NULL, FK → `intertitles(id)` ON DELETE SET NULL |
| `review_status` | text | NOT NULL DEFAULT `'machine'`, `IN ('machine','reviewed')` |
| `created_at` | timestamptz | NOT NULL DEFAULT `now()` |
| `updated_at` | timestamptz | NOT NULL DEFAULT `now()` |

Indexes and constraints:

- `CHECK (end_us > start_us)`.
- `UNIQUE (track_id, sequence) DEFERRABLE INITIALLY DEFERRED` to allow
  transactional reordering.
- Non-overlap per track enforced with an exclusion constraint:

  ```sql
  CREATE EXTENSION IF NOT EXISTS btree_gist;

  ALTER TABLE subtitle_entries
    ADD CONSTRAINT ex_subtitle_entries_no_overlap
    EXCLUDE USING gist (
      track_id WITH =,
      int8range(start_us, end_us, '[)') WITH &&
    ) DEFERRABLE INITIALLY DEFERRED;
  ```

  The service layer validates overlaps first to return a useful error; the
  constraint is the last line of defence.
- `INDEX (track_id, start_us)`.
- `INDEX (source_intertitle_id)`.

### 3.6 `export_artifacts`

| Column | Type | Constraints |
|---|---|---|
| `id` | uuid | PK |
| `track_id` | uuid | NOT NULL, FK → `subtitle_tracks(id)` ON DELETE CASCADE |
| `format` | text | NOT NULL, `IN ('srt','vtt')` |
| `storage_key` | text | NOT NULL, UNIQUE |
| `byte_size` | bigint | NOT NULL, `> 0` |
| `sha256` | char(64) | NOT NULL |
| `entry_count` | integer | NOT NULL, `>= 0` |
| `validation_status` | text | NOT NULL DEFAULT `'pending'`, `IN ('pending','valid','invalid')` |
| `validation_errors` | jsonb | NOT NULL DEFAULT `'[]'` |
| `created_at` | timestamptz | NOT NULL DEFAULT `now()` |

Indexes: `INDEX (track_id, created_at DESC)`,
`UNIQUE (track_id, format, sha256)` to avoid duplicate artifacts for identical
content.

A job may only move to `completed` after the artifact it produced is marked
`valid`.

## 4. Deletion and retention

- Deleting a `media_asset` cascades jobs, intertitles, tracks, entries, and
  export metadata. The application must delete files **after** the database
  transaction commits; orphan files are swept by a script.
- Work directories are ephemeral and removed on success, failure, and
  cancellation.
- Exports are regenerable; losing them is not data loss.
- Uploaded media is retained until explicitly deleted. There is no automatic
  retention purge in v1. A retention policy is a backlog item.
- No media, frames, or exports are stored in PostgreSQL.

## 5. Migration policy

- Alembic is the only mechanism that changes schema.
- Migrations are hand-reviewed even when autogenerated.
- Each migration has a working `downgrade()`; dropping data is called out in
  the migration docstring.
- `alembic upgrade head` and `alembic downgrade base` are tested in CI against
  a fresh PostgreSQL 18 service.
- The app never calls `create_all()` in production and never migrates on
  startup.
- Required extension: `btree_gist` (created in the first migration that needs
  it).
- Seed data is not part of migrations. Tests create their own fixtures.

## 6. Open questions

- Whether `MediaAsset` deduplication by SHA-256 should return the existing
  asset or reject the upload with `409`. M2 decision.
- Whether multiple subtitle tracks per media are needed in the first release
  (language variants). The schema allows it; the UI may create one by default.
